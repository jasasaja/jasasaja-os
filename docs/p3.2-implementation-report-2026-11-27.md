## 1. Ringkasan hasil

Dua endpoint penulisan project ditambahkan ke modul project yang sudah ada: `POST /api/projects` dan `PATCH /api/projects/:projectId`. Request divalidasi dengan Zod `.strict()`; guard session, Origin, Content-Type, dan CSRF existing berlaku otomatis lewat `authGuard`. Project baru dibuat dengan `status: "Planned"` bila tidak diberikan, tanpa milestone/task. PATCH hanya mengubah field dasar (`name`, `description`, `status`) dan tidak pernah meng-auto-complete turunan. Tidak ada perubahan milestone/task, referensi, UI, schema, atau migrasi pada slice ini.

## 3. Perubahan utama

- `POST /api/projects`: menerima `{ name, description?, status? }`, mengembalikan `201` dengan `{ data: { id, name, description, status, milestoneCount: 0, taskCount: 0, createdAt, updatedAt } }`. `description` boleh `null`; `status` default `Planned`.
- `PATCH /api/projects/:projectId`: menerima partial `{ name?, description?, status? }`, minimal satu field harus hadir, mengembalikan `200` dengan ringkasan project yang sudah diperbarui dan hitungan milestone/task aktual dari DB.
- `.strict()` pada kedua skema menolak field yang tidak dikenal, termasuk `stage`; ini menjaga keputusan P3.1 bahwa `status` dipakai sebagai label tahap sampai ada keputusan schema.
- `param projectId` tetap divalidasi sebagai UUID; project yang tidak ada menghasilkan `404 NOT_FOUND` pada PATCH.
- Timestamp memakai `sql\`now()\`` mengikuti pola C2/Asia/Jakarta seperti handler handbook; tidak ada `updatedAt` yang diubah saat request gagal validasi.
- Helper `countProjectChildren` dipakai PATCH agar ringkasan tidak melaporkan `0` untuk project yang sudah memiliki turunan; helper ini tidak mengubah perilaku endpoint baca P3.1.
- Guard/otorisasi, CSRF, dan error envelope memakai infrastructure existing; tidak ada hook atau error handler baru.

## 7. Risiko atau masalah yang ditemukan

- **Istilah `stage` belum tersedia di schema.** PATCH/POST menolak `stage` lewat `.strict()`; kontrak `docs/api-contract.md` §6.4 masih `Proposed` dan memakai `stage`. Tidak ada migrasi/schema change.
- **Belum ada automated backend test.** Endpoint project kini enam handler dengan smoke manual sebagai satu-satunya bukti lokal; utang teknis ini terbawa dari P2/P3.1.
- **Hitungan turunan dibaca terpisah pada PATCH.** Dua query kecil ditambahkan agar ringkasan akurat; untuk dataset besar ini dapat diganti agregasi SQL bila diperlukan, bukan bagian dari slice ini.
- **Web UI belum memakai endpoint ini.** Rute `/projects` masih scaffold; P3.5 akan menghubungkan data nyata.
- **Working tree tetap uncommitted.** Perubahan Phase 1, 2, dan 3 belum di-commit; tidak ada reset/checkout/stash destruktif.
