## 1. Ringkasan hasil

Tiga endpoint baru tersedia di modul handbook: `GET /api/handbook/items/:id/versions`, `POST /api/handbook/items/:id/versions`, dan `POST /api/handbook/items/:id/approve`. Versi baru selalu dibuat sebagai `Draft` dengan nomor monoton; approval dilakukan eksplisit oleh owner dan menurunkan standar lama ke `Deprecated` dalam satu transaksi. Tidak ada auto-approve, edit versi, delete versi, perubahan schema, atau migrasi baru.

## 3. Perubahan utama

- `POST /api/handbook/items/:id/versions`: menerima hanya `{ contentJson, changeNote? }`, menghitung `max(version) + 1`, menyisipkan versi `Draft`, dan memperbarui `updatedAt` item dalam transaksi.
- Penomoran versi diamankan dengan `SELECT ... FOR UPDATE` pada baris item sehingga dua request bersamaan tidak mendapat nomor sama. Unique index `(handbook_item_id, version)` tetap menjadi backstop di database.
- `GET /api/handbook/items/:id/versions`: mengembalikan seluruh riwayat versi terurut dari versi terbesar ke terkecil, lengkap dengan `contentJson` dan `changeNote`.
- `POST /api/handbook/items/:id/approve`: menerima `{ versionId }`; dalam satu transaksi, baris item dikunci, versi target divalidasi milik item dan berstatus `Draft`, versi `Approved` lama diubah ke `Deprecated`, lalu target menjadi `Approved` dengan `approvedAt`.
- Urutan update sengaja "deprecate dulu, baru approve" agar partial unique index `handbook_item_versions_one_approved_uidx` tidak menimbulkan konflik saat pergantian standar.
- `versionId` dari item lain ditolak `404`; status selain `Draft` ditolak `409 CONFLICT`; error envelope mengikuti pola `AppError` yang sudah ada.
- Pembacaan detail P2.1 tetap menunjukkan `activeVersion` dari versi `Approved` terbaru; `latestVersion` dapat tetap `Draft` bila ada revisi baru yang belum disetujui.

## 7. Risiko atau masalah yang ditemukan

- **Drift schema/migrasi tetap ada.** Partial unique index `handbook_item_versions_one_approved_uidx` berada di `0000_init.sql` tetapi tidak dideklarasikan di `server/src/db/schema/handbook.ts`. Tidak ada `db:generate` atau migrasi baru; perlu tinjauan terpisah sebelum perubahan schema.
- **Keamanan konkurensi belum diuji dengan beban paralel.** `FOR UPDATE` pada baris item dan unique index diharapkan cukup, tetapi bukti smoke hanya berurutan. Ini dicatat, bukan diklaim terverifikasi.
- **`latestVersion` bisa berstatus `Draft`.** Ini disengaja menurut B1: standar aktif mengikuti `Approved`, sedangkan versi terbaru dipakai sebagai label editorial. UI P2.5 harus menampilkan keduanya secara jelas.
- **Belum ada automated backend test.** Endpoint tumbuh menjadi 8 handler dengan logika transaksi; smoke manual menjadi semakin rapuh. Disarankan slice test backend terpisah bila disetujui.
- **Perbaikan P2.2 di `app.ts` tetap berlaku.** Tidak ada perubahan error handler baru pada slice ini.
