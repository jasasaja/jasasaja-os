## 3. Perubahan utama

- `GET /api/handbook/categories`: daftar kategori diurutkan oleh `sortOrder` lalu `name`.
- `GET /api/handbook/items`: filter `categoryId` (UUID), `status` (`Draft|Approved|Deprecated`), dan `q` (pencarian case-insensitive pada judul/ringkasan). Query yang tidak dikenal ditolak `400`.
- `GET /api/handbook/items/:id`: detail item, seluruh riwayat versi, `activeVersion` (hanya `Approved`, terbaru), dan `latestVersion` untuk label editorial.
- Resolusi standar aktif memakai versi `Approved` bila ada; bila tidak ada, `activeVersion: null` dan `status` mengikuti versi terakhir.
- Karakter wildcard LIKE (`%`, `_`, `\`) dinetralisir menjadi spasi agar `q` tidak berubah menjadi pola wildcard.
- Semua endpoint tetap berada di balik guard owner, CSRF, dan error envelope yang sudah ada.

## 7. Risiko atau masalah yang ditemukan

- **Bentuk `contentJson` handbook belum final.** Endpoint mengembalikan konten apa adanya; kontrak field `purpose`/`whenToUse`/dll. baru akan dibentuk di P2.2.
- **`meta` pagination belum ada.** Sesuai rekomendasi backlog, respons mengikuti pola `{ data: [...] }` dari modul learning dan gap `meta` dicatat, bukan ditambahkan diam-diam.
- **Drift schema/migrasi.** Partial unique index `handbook_item_versions_one_approved_uidx` ada di `0000_init.sql` tetapi belum tercermin di `server/src/db/schema/handbook.ts`. Tidak ada migrasi baru dibuat; perlu tinjauan terpisah sebelum `db:generate`.
- **Belum ada automated backend test.** Verifikasi slice ini mengandalkan smoke manual + cleanup; ini tetap menjadi known gap Phase 1/2.
